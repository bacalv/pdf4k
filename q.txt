Yes — PowerPoint can do this, though not with a built-in shape. You add a small add-in called Web Viewer (published by Microsoft), which embeds a live, interactive web page that renders both while you're editing and during the slideshow.

Here's how to add it:

Open your presentation and go to the slide where you want the page.
On the ribbon, click Insert → Get Add-ins (or Insert → Add-ins → Get Add-ins).
Search for Web Viewer, then click Add to install it. A placeholder box appears on the slide.
In that box, paste the page's URL — but with an important catch: enter it without the https:// prefix (e.g. type en.wikipedia.org, not https://en.wikipedia.org), then click the arrow/Preview button.
Resize and position the box like any other object. Run the slideshow (F5) and the page will be live and clickable.
A few things worth knowing:

Not every site will load. Pages that block being shown inside a frame (via X-Frame-Options/Content-Security-Policy) will appear blank. Google, YouTube watch pages, many banking and login sites do this. YouTube embed links and most public info sites work fine.
You need an internet connection when presenting, since it's pulling the page live. If connectivity is a risk, keep a screenshot as backup.
It only works in PowerPoint versions that support add-ins — Microsoft 365, PowerPoint 2016/2019/2021 on Windows and Mac, and PowerPoint on the web. It does not work in older versions or in the mobile apps.
If add-ins are blocked in your organization, the older alternative is the third-party LiveWeb add-in, which uses macros to achieve the same thing, but it requires enabling macros and a manual install.

Good news — the Web Viewer add-in already does exactly that. During Slide Show mode (F5), the embedded page isn't a picture; it's a live, interactive frame. You and your audience can scroll, click links, fill in forms, play embedded video, and navigate within the site — the same as a browser window sitting inside the slide.

A few realities to set expectations, though:

The interaction happens in the slideshow, not in edit view. In normal editing mode you mostly see a static preview; the full click-and-type interactivity kicks in when you actually present. So if you're testing it, run the slideshow rather than judging it from the edit screen.

It behaves like an embedded browser frame, which means the same framing restrictions apply — sites that refuse to be embedded (Google search, YouTube watch pages, most login/banking pages) will show blank or an error no matter what, because they block being loaded inside another page. There's no setting in PowerPoint that overrides this; it's the website's choice. Public sites, dashboards, documentation, internal tools that permit framing, and YouTube embed links all work well.

It's a single frame with no browser chrome — no address bar, back/forward buttons, or tabs. People navigate by clicking links on the page itself. If someone clicks a link that tries to open a new tab or a blocked site, it may just fail silently rather than pop out. If you need a proper back button or an address bar, that's beyond what the add-in offers.

If what you're picturing is closer to a full mini-browser — arbitrary URLs, back/forward, handling of sites that block framing — then PowerPoint's add-in won't get you all the way there, and you'd be better off either alt-tabbing to a real browser during the talk, or using a screen-capture/embedding tool.

So the honest answer: for interacting with a framing-friendly site, the Web Viewer add-in gives you genuine browser-like interaction right in the slide.
